# 高级分析工作区

「观测 → 高级分析」提供三个独立页面，不新增 Core API 或改变统计与流控语义：

| 页面 | 前端路由 | 数据与操作边界 |
| --- | --- | --- |
| 可观测看板 | `/analytics/observability` | 历史请求延迟、缓存与错误；不依赖 Flow 能力 |
| 流控看板 | `/analytics/flow` | 当前受控调用、排队、观察会话趋势与运行策略检查；不读取或写入 YAML |
| 流控配置 | `/analytics/flow/config` | 独立草稿、规则、队列与观察设置；差异确认后保存 |

`/analytics` 默认进入可观测看板。旧 `/flow-control` 和 `/config?section=flow-control` 重定向到流控配置。两个流控子页沿用 Core 能力门控；能力不存在时不隐藏可观测看板。新路由纳入连接页面恢复名单。

## 用量与分析边界

`/usage` 保留请求、Token、费用、健康状态、模型占比、API/模型/凭据明细、请求事件、定价及完整导入导出。四张性能与可靠性图表移到可观测看板；用量页保留携带时间范围的入口，不重复加载分析明细。

可观测页首次直接打开默认最近 24 小时，URL 时间范围优先。进入请求事件时把当前可见相对窗口固定成绝对起止时间。自定义范围无效时不查询明细。

查询模式下，不超过 7 天自动逐页加载，超过 7 天或全部范围手动触发。四张图共用一份明细。页面分别展示尚未加载、加载中、完整结果、部分失败、用户停止和确实无请求；有样本但指标缺少有效测量时不假装为零。部分结果必须带提示，不把分页前缀当成随机抽样或全窗口最终统计。重新加载从第一页开始，避免拼接不一致快照。

离开页面或更换连接、窗口、查询快照会中止旧请求。分析不增加后台轮询或持久化请求明细。

## 流控边界

看板复用 `useFlowControlStatus`、`LiveMonitor` 和运行策略模式的 `RuleInspector`。预览仍是手动有界读取，不预留许可；实际规则与本阶段容量由 Core 解释。趋势只包含本次观察的最近数据，不是历史监控。关闭流控后的新调用不计入受控摘要，因此不能标为全站并发。

配置页不挂载实时观察。查看未保存草稿、已保存期望配置、Core 已应用开关；保存仅合并 Flow 脏字段至最新 YAML，保留其他字段与注释，确认期间基线变化时重新生成差异。保存后重新读取状态，文件保存成功不等于运行策略生效。离开配置页仍受未保存保护。

## 验证

- `npm run validate:lts`：单元测试、契约、类型、lint 与构建。
- 浏览器检查三页导航、旧入口、时间窗口、明细取消、Flow 实时启停、配置保存保护、主题与移动端。
- Mock 与临时真实 Core 检查分别记录，不把构建或 Mock 通过当成生产部署验收。
