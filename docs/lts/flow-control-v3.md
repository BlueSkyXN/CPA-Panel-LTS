# Flow Control V3：模型集合、单一账号与联合调度

## 交付定位

本次将原 Flow V3 的功能移植到 2026-09-06 发布基线：Core `664644517cb827f987dd98cae5815fe633746b65`（v1-lts-0.0.23），Panel `150858399a234ad6fd6279cbe13983384395c599`（v1-lts-0.0.15）。这两个基线原来都没有 Flow，也不包含独立的 Codex Identity 批次；本次不引入该批次，保留现有 `codexmetadata` 语义、usage v3 及已合并的本地开发工作。

默认不启用流控、实时观察或资源采样，不修改 UA 模板、依赖或模型目录。以下 V1/V2 兼容描述只针对历史 Flow 配置，不表示本次要逐版应用旧补丁。产品功能见本文；本轮实际测试及移植记录见交付根目录 `TEST_RESULTS.md` 和项目 `local/flow-v3-rebase/`。完整构建仍需正确工具链和锁定依赖。

## 一、对象与规则

三个主要对象：调用方 Key（访问 CPA 的 Key）、模型、上游账号（一个 Auth 认证记录，账号＝凭据）。OAuth 文件和配置中的上游 API Key 都作为 Auth 记录处理。

V3 上游账号引用只来自 Provider 命名空间和 `Auth.ID`，不按邮箱、远程 account_id、Token、原 flow_control_group 合并。复用 V2 单凭据的引用格式，便于明确迁移；旧版本适配器仍保留旧计算，仅服务于未迁移配置和迁移建议。刷新 Token 不改变 Auth.ID 就不重置身份。相同账号字符串出现在两份不同 Auth 记录中，也不在 V3 自动合并。

规则分三件事：

1. **筛选**：`keys/models/accounts` 是复选范围。同字段内 OR，字段之间 AND。省略表示全部（包括将来新增对象）；显式空数组 `[]` 不表示全部，启用时拒绝。重复值去重，同规则精确项与前缀重复命中也只计一次。
2. **分组**：`scope: custom` 加 `group-by`。不包含 model 则匹配模型共享计数；包含 model 则按具体模型分别计数。空分组表示本规则所有匹配请求共享一个总量。`key/account/model` 的八种子集均支持；Provider、认证类型可作高级筛选，旧命名 scope 继续兼容。
3. **限制**：`max-concurrent` 控制进行中数量；可选 `windows` 对多个滑动时间窗同时限制。纯并发不写频率历史，不是令牌桶。

所有匹配规则取交集，没有“后者覆盖前者”“具体规则覆盖全局规则”。每条规则 ID 是计数的一部分。两个相交集合是两个独立约束，同一模型命中两条时同时占位，实际执行总数仍只增加一次。

### 共享、独立与交叉

| 规则 | models | group-by | 含义 |
|---|---|---|---|
| shared-12 | [m1,m2] | [key,account] | 每个调用方×账号，m1+m2 合计上限 |
| shared-23 | [m2,m3] | [key,account] | 每个调用方×账号，m2+m3 合计上限 |
| each-model | [m1,m2,m3] | [key,account,model] | 每个三者组合独立上限 |

m2 必须同时满足三条，不会任选一条；完成 m1 后只会重新检查等待者，不保证 m2 立即可执行，因为另一组仍可能满。

### 模型名称

请求层按现有解析获得的请求别名计；执行层按实际传入 Executor 的模型计，不为了限流轮转别名池或改写请求模型。执行层支持 `provider::model` 明确引用，例如 `codex::model-a`。不带 Provider 的名字匹配各 Provider 的同名模型；V3 按模型分组的计数会自动带上实际 Provider，防止把不同提供方的同名目标误当一个模型。需要跨 Provider 合计时，复选目标后不按 model 分组。

精确名称优先作为可视选择；一个显式末尾 `*` 允许前缀集合，可能包含未来模型。没有隐式子串匹配、昵称推断、集合嵌套或单独模型组数据库。模型复选不把一次请求扩展为多个模型调用。

## 二、执行与排队

```text
原有鉴权与请求解析
        ↓
创建逻辑调用（尚未占运行名额）
        ↓
原选择器选择合法账号，保留会话、模型和冷却约束
        ↓
联合检查 request + attempt 全部命中规则
   ├─ 不满足 → 一项有界等待，不持有首次运行名额
   └─ 满足   → 同一个 Engine 锁内一起提交
                    ↓
            再检查账号生命周期与可用性
                    ↓
              原 Executor 执行
                    ↓
               真实生产端结束
                    ↓
      释放一次 → 唤醒等待者重新判断全部条件
```

`request` 是一次 Manager 逻辑操作；`attempt` 是一次 Manager 对 Executor 的调用，不是每个底层 TCP 包。首次 `request` 与 `attempt` 一起申请，任意约束不满足就不增加本次运行计数。调用内部重试保留逻辑名额；前次尝试结束后再申请下一次尝试名额。并行副本分别计执行名额；有活跃尝试或已有待启动尝试的逻辑调用，不再排队额外副本。

队列由调用方间轮转、各调用方最早可执行项组成。已经可执行的老等待者先获得机会；不能执行的队头允许跳过。计数申请是原子操作，选择器的容量查询只是提示，不承诺之后必然获得名额。

队列设置：总等待数、每 Key 等待数、正文登记字节、累计等待毫秒。首次与后续重试的等待累计在同一逻辑操作中，不把模型生成时间计作排队。原 context 的截止时间优先。排队取消立即移除，不事后补发。`max-waiting: 0` 或 V3 `max-wait-ms: 0` 表示不等、直接返回本地繁忙。登记字节不是进程总内存，入口已读取正文、副本、连接和生成缓冲有独立成本。

没有固定目标时，现有候选选择可以参考容量；选定并入队后不动态更换账号，不更换模型、不迁移依赖的 WebSocket。公平是启动机会上的轮转，不保证 Token/费用/运行时长均等，也不保证复杂相交集合的等待者一定在截止时间前成功。

## 三、释放与错误

200、首个 Token、`ExecuteStream` 返回流对象都不是结束。`HoldChannel` 等待实际生产端关闭；消费者取消但生产端仍在输出时显示 draining，仍占名额。生产者永久忽略取消时继续占用，不能用 TTL 假装结束；这类 Executor 问题需真实取消或修复。

已收到执行许可但尚未进入 Executor 的目标变更可以撤销许可，退回未发送的时间窗记录；已执行后失败不退请求频率记录。重复取消、关闭、释放只处理一次。逻辑调用结束与多个实际生产端结束互相独立，最后一个生产者结束前不漏计仍运行的尝试。

本地 busy/queue-full/wait-timeout/target-changed 不将上游账号判失效、不写上游额度冷却、不触发本地模型替换。原有 Codex 连续性登记与等待配合：正常路径等取得许可后再登记；已预留的特殊连续性路径不进入新等待队列。现有 Home 仍与本地 enabled 流控互斥。

## 四、配置更新

没写 version 或 version<=2：旧执行语义保留，不能静默变成 V3。新 Panel 必须先请求迁移建议，确认一对一 Auth 引用后，显式保存 `version: 3`。

跨 legacy/V3 的变更在已有活动记录或等待项时被 Engine 原子拒绝，旧策略和许可不被清空。先停止新增调用、等待旧工作结束，再切换。Manager 会标记配置应用失败并阻止新的受控请求，直到恢复旧配置或在无在途工作时重新提交；仅等待并不自动重新尝试加载失败配置。

纯并发规则热改分组/模型集时，对活动身份重新投影，结束回调释放更新后的所属计数。降低上限不杀已有流，新请求等自然回落。正常改标签、规则顺序不重置计数。

频率历史只有时间与许可 ID，没有完整已结束请求的身份历史。**仍有频率记录时，同一规则 ID 改筛选/分组会被拒绝**，以免错用旧集合历史。使用明确的新规则 ID（明确开始新的频率历史），或等旧记录到期后再改。新加入的时间窗不回溯此前未留存的历史。本版不新增历史数据库来解决这类低频管理操作。

## 五、观察开关与资源

三个主开关：执行 `enabled`、允许实时 `observation.realtime`、资源指标 `observation.resources`。后两项默认 false，可独立于执行开关。手动汇总、详情、规则解释按需可读，不各自再加总开关。

实时订阅共享一份小汇总及已编码 JSON，默认2秒，500..30000毫秒可调；默认4个观察者、最多16。关闭实时结束既有观察连接，拒绝新观察连接；Panel 不转为自动轮询。页面默认不自动观察，标签页隐藏暂停，断线只重连观察而不重试业务调用。较长更新周期同步调整前端 watchdog。

实时消息不携带完整配置、模型目录或请求详情。仅汇总计数、最近等待判定的阻塞直方图（不冒充所有约束的实时全量解释）、采样时间和策略版本。目录首次/手动加载或策略版本改变才读取。浏览器趋势固定最多60点，不落盘。

手动详情先筛选、分页选中记录，再解释选中的等待项；默认100最多200，偏移最多10000。当前实现页面解释仍在短查询锁内执行，成本随所选记录×规则数增长；不是“完全锁外、常数时间”。高偏移仍需扫描活动记录。观察开销与调度正确性分开测试，不承诺零影响。

资源采样由真实读取触发：Go heap对象、Go-managed内存和goroutines缓存5秒；当前工作目录所在文件系统可用空间缓存30秒，Linux/Darwin实现，其他系统返回未知。不展示假CPU/RSS，不遍历日志目录，不开常驻采样线程，不持久化监控历史。`.dockerignore` 排除 local/，交接资料仍保留在源码包中。

## 六、Panel

删除固定五规则/固定模型场景向导。通用规则：选择范围（调用方/模型/账号多选）、合计/分别计数、上限、高级 Provider/类型/频率窗口。全部模式包含未来对象，勾选当前结果保存固定列表；清空选择保持 [] 错误，不偷换为全部。暂时不在目录中的已保存引用继续显示并保留。

规则自动生成自然语言；模型相交矩阵通过 Core POST preview 得到同一时刻、同一策略版本的匹配结果，没有前端第二套放行算法。草稿和实际策略分开；缺少账号信息、目标与账号 Provider不符、引用不存在或草稿更换计数域导致用量不可比时，返回 unknown/incomplete，不填零。

一次预览最多24个明确目标，禁止前缀作目标身份；仅看当前约束，不占位，也不证明路由/套餐一定支持该模型。两层首次启动要一起满足，单阶段预览不能当完整请求已获许可。

## 七、刻意不做

不引入账号组/去重，Redis、分布式计数、持久队列、TPM预测、自动涨降并发、事件回放、跨模型容量借贷或实时历史库。参数示例只在文档和测试，不是官方限额。

覆盖沿用 V2 Manager 控制链。`Manager.HttpRequest`、插件绕过 Manager 的网络请求、独立实时 relay、空闲 WebSocket 连接、后台异步任务实际生命周期不自动纳入。Executor 内部网络重试仍属于一次 attempt。未启用时开始的旧调用无法回溯计数。多实例使用同一账号不共享这份进程内名额。完整构建和集成测试必须由本地完成。

# V3 管理 API

沿用现有 `/v0/management` 和管理认证；没有新写入接口，配置保存沿用 `/config.yaml`。

| 方法/路径 | 用途 |
|---|---|
| GET `/flow-control` | schema3能力、实际策略、轻量汇总、调用方与唯一账号引用、模型目录 |
| GET `/flow-control/summary` | 按需汇总，不扫描目录，不构造请求明细 |
| GET `/flow-control/events` | 开启 realtime 后可订阅共享摘要；关闭返回409，人数满返回503 |
| GET `/flow-control/details` | 手动分页 `offset=0&limit=100`，可加 stage/state/key/account/model |
| POST `/flow-control/preview` | `{config?: <草稿>, targets: [<Identity>...]}`，同版本批量解释 |
| POST `/flow-control/migration-preview` | 直接提交旧 flow-control 配置块，返回 config/issues/ready；只读 |
| GET `/flow-control/explain` | 旧单目标查询保留，条件解释，不替代路由探测；新 Panel 使用 POST preview |

POST 最大1MiB；preview1..24目标，每项字段有长度限制，不能拿前缀作实际目标。details最多200行、offset最多10000；拒绝非整数和未知stage/state。活动明细总数和truncated标志区分输出截断与真实总量。

`schema-version` 是 API 版本；`policy.version` 是运行规则语义，不要混淆。`configured-enabled` 对应文件配置，`policy` 是已经应用的策略，`configuration-error` 表示当前配置未成功应用。Panel 不把未保存草稿显示成实际策略。

`keys[].ref` 是现有调用方引用，`accounts[].ref` 是唯一Auth引用。不要传入原始CPA Key、OAuth Token或AI Key。`model-options` 中的 provider::model 可用于规则复选；preview Identity 则拆为 `provider` 和 `model`。

示例（请用当前接口实际ref，以下用anonymous和泛化模型表达）：

```json
{
  "targets": [
    {"stage":"attempt", "key":"anonymous", "provider":"codex", "model":"model-a"},
    {"stage":"attempt", "key":"anonymous", "provider":"codex", "model":"model-b"}
  ]
}
```

每个结果含 `matches`、`known`/`unresolved`、`active`、`blocked-by`、`delta`、`complete`、`can-start`、`policy-revision`和采样时间。未选账号时涉及账号的约束未知；预览不会申请真实名额，结果可能在返回后变化。详情分页也是即时视图，不是游标冻结快照，活动变化会导致翻页时位置变化。

SSE：初次立即一份汇总，之后按interval更新，所有观察者复用一份缓存；关闭发送 `event: disabled` 后结束。每个连接只顺序写最新汇总，无历史补发；断线客户端拉取最新值。schema3汇总不再含V2全量activity/buckets/policy，外部V2观察程序应升级；不要用字段缺失推断为零。

资源 `filesystem-free-bytes: null` 表示未知；磁盘挂载点为进程工作目录所在文件系统，不是日志目录大小，也不是流控磁盘使用。Go-managed内存不是RSS。
