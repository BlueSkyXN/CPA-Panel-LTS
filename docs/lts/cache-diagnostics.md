# 缓存请求诊断

扩展现有请求明细，展示账号选择、亲和匹配和上游缓存报告三个独立事实。现有 usage 汇总、价格、导入导出保持兼容。

## 展示规则

- 原始字段有效零、字段缺失和旧记录未知分别显示，不把未知记作明确零读取。
- 只展示 Core 实际记录的选择、候选和改写事件；当前索引未找到候选不展示虚构的拒绝原因。
- 用量记录、逻辑请求和每次出站尝试明确关联。第一次凭据失败与后续成功结果不能拼接。
- `comparison_response_not_found` 显示比较记录不可用；`unavailable` 显示未得到可用结论。
- 本地前后请求对比不冒充调用时产生的官方诊断。
- 指定会话查询使用只读管理接口；展示当前实例、采集时间和截断状态。上游 KV 不属于 CPA 内存视图。
- 查询详情按用户展开触发；旧 Core 不支持时保留原有明细，显示新增诊断不可用。
- 四种语言保持相同键及插值结构，支持键盘、窄屏和已有主题。

## 验收

覆盖明确零/正值/缺失/旧记录、诊断四种官方类型、两次出站尝试、unsupported/unbound/bound 查询、错误与结果截断。异步响应不得写回已切换连接或已选择另一条记录的详情。

## 数据边界

用量行的 `request_id` 关联执行 UUID，`diagnostics_id` 关联本次逻辑请求，`diagnostics_instance_id` 标明来源实例。实例不同或详情 404 时显示记录不可用，不按账号、时间或相同 ID 猜测。面板连接代次变化时，尚未完成的请求结果会被丢弃。

用户展开已有行的诊断区后，读取 capabilities 与指定请求；出站尝试展示选择决定、执行 ID、账号、认证方式、实际出口类别、HTTP/响应状态、原始缓存字段路径、比较 ID 发送状态和官方返回。按需展开出站字段可查看安全标量值与内容/PCK 摘要。输入长度单位沿用 Core 原义，`canonical_turns` 与 `strict_input_items` 不换算成 tokens。

会话查询使用只读 POST，不产生连接切换的写操作锁。账号/LCP 绑定与最近一次记录的 OAuth 作用域分别展示；未知身份、插件调度或记录缺失可导致不同部分不可用。当前对象列表与历史决定独立，查询不重做匹配。

本地对比手动输入另一条同实例诊断 ID，比较两条入口 JSON 摘要。它不自动补发模型请求、不自动选择历史 A 模型基线。记录内容、保留窗口和上限由 Core 决定；面板显示截断状态，不把超限删掉的数组视为完整列表。

对比包含 Core 返回的各协议内容摘要，例如 `input`、`messages`、`contents` 和系统指令；这些字段只展示摘要，沿用最多 32 个字段的解码边界。

## 验证入口

- `npm run test:usage-cache`：零/缺失/无效/旧记录、两次尝试、JSON 摘要比较、连接 ABA 防护。
- `npm run validate:lts`：现有统计、连接、API、契约、类型、Lint 和单文件构建。
- `python3 scripts/smoke-cache-diagnostics.py`：本机 mock Core 下检查详情、查询、错误和窄屏，无模型调用。

长连接后续 create/append 的差异对比优先使用该次执行准备阶段的输入摘要，缺少这项证据时使用父请求入口；服务端自动 successor 不显示成一次虚构的客户端发送。
